# Maven Central publishing

Verified organization namespace: io.github.vyrnforge. Runtime packages remain io.vyrnforge.platform.kernel.*. Three library JARs, plus six documentation archives and the parent POM. Version 0.3.0 is immutable and remains on GitHub Packages.

Release PRs must pass protected CI, CodeQL and dependency review. A version-changing main push with a release: prefix (or owner manual dispatch on main) triggers publishing. A single build produces the release files. The workflow checks the exact inventory, contract baseline, test suite, sources and Javadoc, stages four POMs and nine JARs, signs with the dedicated public fingerprint, and uses the Sonatype Publisher API for automatic validation and publication. It mirrors the same POM/JAR bytes to GitHub Packages and only creates the GitHub Release after both destinations succeed.

Secrets: CENTRAL_USERNAME, CENTRAL_PASSWORD, GPG_PRIVATE_KEY, GPG_PASSPHRASE. GPG_REVOCATION_CERT is recovery-only. No secrets in PR builds. Revoke temporary SIGNING_BOOTSTRAP_TOKEN after bootstrap. See [signing key operations](signing-key-operations.md) for the public fingerprint, expiry, rotation and outstanding owner-controlled backup/revocation procedure. GitHub Secrets are not a readable backup.

Recovery: do not rerun a failed upload blindly. Check Central Portal Deployments for the version and deployment ID. If pending/publishing, wait or investigate. If failed, drop only the failed deployment after reviewing errors. If published, never replace it. Manual recovery must check the exact published bytes before mirroring; any partial GitHub package deployment must be reconciled file-by-file, not overwritten. If the original build cannot be reproduced exactly, retrieve the published artifacts from Central. Never bump a version just to conceal a partial publish.

Official requirements: https://central.sonatype.org/publish/requirements/ and https://central.sonatype.org/publish/publish-portal-api/.

## Reconciliation without re-upload

For a timed-out deployment, add a reviewed JSON record under `docs/releases/recovery/<version>.json` containing version, deploymentId, original sourceCommit, and signing fingerprint. Run the existing **release** workflow on main with `recovery_record` set to that path. The v0.3.1 record is checked in; its original deployment reached PUBLISHING before the client timed out. The recovery job checks the existing deployment using the Central status API, requires PUBLISHED, downloads all 13 signed Maven payloads, verifies signatures and original source POM bytes, runs an anonymous consumer smoke, mirrors the exact payloads, and creates the GitHub Release at the original source commit. It never uploads or drops a Central deployment. If state is not PUBLISHED, stop and inspect Portal or contact Sonatype support. A successful recovery does not modify existing versions or tags. The first reviewed recovery record triggers the reconciliation job via a main push with merge title `ops: reconcile Central`.
