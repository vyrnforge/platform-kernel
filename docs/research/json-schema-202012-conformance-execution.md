# JSON Schema 2020-12 conformance — first executable verifier

**Status:** proposed test-only PR, not a contract version or public Kernel API. Baseline `71dcd337fb2ac2fd5515a8bb711cbb09dd5a718e`; published v0.3.2 unchanged. Related [PV-01..PV-40 design](portable-behavior-vectors-spec.md), [existing v0.1/v0.2 compatibility checker](../../scripts/check-contract-compatibility.py) and [pattern register](../strategy/kernel-pattern-register.md).

## Precise scope
- `scripts/test-json-schema-202012.py` loads **all eleven** released v0.2 schemas and four original examples into a **local-only** `referencing.Registry`, checks each schema's meta-schema under `jsonschema.Draft202012Validator` and exercises a matrix of minimal valid/required-missing/additive unknown optional shapes.
- Negative/edge cases: absent vs null, TENANT vs NONE (and forbidden DEPLOYMENT), actor enum and blank identifier, event payload object, event version, UUIDv7 canonical regex, opaque cross-system file ID, invalid byte count, large JSON integer shape, UTC suffix. Explicitly **compares** `format` annotation (no format checker) with strict `FormatChecker` + RFC3339 plugin. Does not claim date-time validation from `Z$` alone.
- Existing CI `verify` runs an isolated **test-only** Python 3.14.10 virtualenv, with the SHA-pinned `actions/setup-python` action and `scripts/requirements-schema-202012.lock`. All seven resolved packages (including transitive dependencies) have exact versions and PyPI wheel SHA-256 hashes, and pip enforces `--require-hashes --only-binary=:all:` plus `pip check`. The native `rpds-py` wheel hash is for CPython 3.14 / Linux x86-64; an environment change must intentionally refresh/review the lock, not silently select a different wheel. No package becomes a Maven production dependency or published JAR dependency. Independently review the workflow, interpreter provenance and the ongoing trust in PyPI/GitHub-hosted actions before merge.

## Limits, acceptance and review
This is structural JSON Schema validation of existing synthetic instances, **not** token/tenant authorization, dynamic API behavior, distributed replay, Java/JS interoperability proof or 40 fully executed PV vectors. It must not silently tighten released v0.2, override the historical v0.1 checker, or fetch remote schemas. Independent human Security/QA/CI supply-chain review remains required (the previous docs-only exception does not apply to workflow changes). Protected checks and exact execution count must pass before recommending merge. Any future change to schemas or new validator dependency in production is **out of scope**. No IAM/Storage product work, no release or deployment.
