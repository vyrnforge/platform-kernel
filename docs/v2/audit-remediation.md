# Kernel audit remediation (v0.3.2 maintenance patch)

Scope: K-A01–K-A04 from the 14 November 2026 audit. No new service, domain ownership, JAR or contract schema version. Artifact version 0.3.2.

- Fingerprints use versioned length-delimited field encoding, explicit nulls, structured actor fields and canonical JSON. New writes use the new hash. A historical hash is accepted only if every persisted content field matches the incoming record. No historical row is rewritten. Existing matching retries remain supported. Stop/drain old intent writers before rollout: old binaries cannot replay new fingerprints. Do not roll back to old writers on a database containing new fingerprints without a separately reviewed migration/recovery plan.
- Audit tenant policy: a tenant-owned resource must match the audit tenant; no tenantless audit of a tenant-owned resource. Global resources may be audited in a tenant scope only when the application authorizes that global operation. Denied cross-tenant attempts should use a safe caller-tenant security event without exposing the other tenant's resource. Existing historic inconsistent records require product-owned review; do not rewrite audit history.
- Runtime rejects invalid UUIDv7 tenant IDs, invalid namespaced module/resource keys, oversized event/audit fields and obviously non-object event payloads. Domain DTOs remain supported; JDBC validates the serialized JSON object shape. Other transport adapters must enforce the released schema at serialization. v0.1/v0.2 JSON schemas remain immutable. Stricter validation is an intentional behavior change.
- ModuleEntitlementPort returns the effective decision at lookup time. Scheduling, expiry and revocation are provider-owned; effectiveAt is metadata, not a kernel licensing engine. Providers must not expose future scheduled enabled state as current. The request pipeline independently rejects a future effectiveAt using its injected Clock. Real provider acceptance remains a product integration task.
- Regression tests cover delimiter and null collisions, legacy replays, different-content conflicts, audit tenant scope and runtime schema limits. Protected CI is required before merge. The v0.3.2 maintenance release incorporates PRs #33 and #37.
